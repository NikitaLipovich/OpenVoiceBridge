## 2. Как это работает (в двух словах)

```
Телефон (звонок)
      │ Bluetooth HFP
      ▼
FSC-BT1036  ── I2S (BCLK/WS/DO) ──►  ESP32-S3
  (HF role,                             │
  I2S slave)                            │ Wi-Fi UDP (порт 5004)
                                        ▼
                                       ПК
                                  udp_capture.py
                                  → call.wav
```

**ESP32-S3** является мастером I2S — он генерирует тактовый сигнал (BCLK, WS).
**BT1036** работает в режиме slave — он просто гонит данные в такт с ESP32.
По умолчанию BT1036 работает как мастер — это нужно изменить через AT-команды (Шаг 2).

## 3. Шаг 1 — Прошивка ESP32-S3

### 3.1 Отредактируй настройки в `main/main.c`

Открой файл и измени три строки:

```c
#define WIFI_SSID       "имя_твоей_сети"
#define WIFI_PASS       "пароль_сети"
#define UDP_REMOTE_IP   "192.168.1.50"   // IP твоего ПК в локальной сети
#define UDP_REMOTE_PORT (5004)
```

Узнать IP ПК:
- **Windows:** `ipconfig` — смотри IPv4 Address в разделе Wi-Fi
- **Linux/macOS:** `ip addr` или `ifconfig`

### 3.2 Плата ESP32-S3-DevKitC-1 v1.1 — разбираемся с кнопками и USB

Прежде чем прошивать — разберись с физикой платы, иначе ничего не заработает.

#### Два USB-разъёма на плате

```
┌─────────────────────────────────────────────────────────┐
│              ESP32-S3-DevKitC-1 v1.1                    │
│                                                         │
│  [USB]                                      [UART]      │
│   ▲                                           ▲         │
│   │                                           │         │
│  Native USB                           USB-to-UART       │
│  (ESP32-S3 встроенный USB)            (чип CP2102N)     │
│  → USB HID, OTG, JTAG                → прошивка и      │
│  → НЕ используем для прошивки          монитор порта    │
│                                                         │
│  [BOOT]                                      [RESET]    │
└─────────────────────────────────────────────────────────┘
```

| Разъём | Маркировка на плате | Для чего |
|--------|---------------------|----------|
| **UART** (правый, ближе к надписи UART) | `UART` | **Прошивка + Serial Monitor** — подключай сюда |
| **USB** (левый) | `USB` | Нативный USB ESP32-S3 — для OTG/HID, сейчас не нужен |

> **Подключай кабель в разъём с маркировкой `UART`** — именно он идёт через CP2102N и виден в системе как COM-порт (Windows) или /dev/ttyUSB0 (Linux).

#### Две кнопки на плате

| Кнопка | Что делает |
|--------|------------|
| **RESET (EN)** | Перезагружает ESP32-S3. Нажми — чип стартует заново. |
| **BOOT (IO0)** | Переводит чип в режим загрузки прошивки. Сама по себе ничего не делает — важна *в момент старта*. |

#### Как войти в режим загрузки (Download Mode)

`idf.py flash` делает это **автоматически** через управляющие линии CP2102N — в большинстве случаев ничего жать не нужно.

Если автоматически не получается (ошибка `Failed to connect to ESP32-S3`):

```
1. Зажми и держи кнопку BOOT
2. Не отпуская BOOT — нажми и отпусти RESET
3. Отпусти BOOT
4. Запускай idf.py flash
```

Чип теперь ждёт прошивку. После успешной прошивки нажми RESET для старта.

#### Определи COM-порт (до подключения кабеля и после)

**Windows:**
```
Диспетчер устройств → Порты (COM и LPT) → Silicon Labs CP210x → COMx
```
Или в PowerShell:
```powershell
[System.IO.Ports.SerialPort]::getportnames()
```

**Linux:**
```bash
ls /dev/ttyUSB*   # обычно /dev/ttyUSB0
```

**macOS:**
```bash
ls /dev/cu.usbserial*
```

### 3.3 Собери и прошей

```bash
# Установить ESP-IDF если не установлен:
# https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/get-started/

idf.py set-target esp32s3
idf.py build
idf.py flash monitor
```

`idf.py flash monitor` сам определяет порт. Если не определяет — укажи явно:

```bash
idf.py -p COM3 flash monitor        # Windows
idf.py -p /dev/ttyUSB0 flash monitor  # Linux
```

После успешной прошивки ты должен увидеть в мониторе:
```
I (1234) audio_stream: connected to AP
I (1235) audio_stream: got ip:192.168.1.XXX
```

Для выхода из монитора: **Ctrl+]**

Если видишь `failed to connect to AP` — проверь SSID/пароль и попробуй снова.

> **Важно:** до подключения BT1036 к I2S пинам ESP32 может выдавать предупреждения или тишину — это нормально на данном этапе.

## 4. Шаг 2 — Настройка FSC-BT1036 через AT-команды

Это нужно сделать **один раз**. Настройки сохраняются в flash модуля.

### 4.1 Подключение для AT-команд (UART)

Подключи USB-UART адаптер к модулю:

```
USB-UART адаптер        FSC-BT1036
────────────────        ──────────
    TX          ──────►  P1 (UART_RX)
    RX          ◄──────  P0 (UART_TX)
    GND         ────────  GND
    3.3V        ────────  VDD
```

> **Никогда не используй 5V** — модуль работает на 3.3V!

Пин P15 (RESET) нужно подтянуть к 3.3V через резистор 10 кОм. Если оставить висящим — модуль может не запуститься.

```
3.3V ── 10kΩ ── P15 (RESET)
```

### 4.2 Открой терминал

Настройки порта: **115200 baud, 8N1, без аппаратного flow control**

- **Windows:** используй PuTTY или Termite
  - Connection type: Serial
  - Speed: 115200
  - COM-порт: смотри Диспетчер устройств → Порты (COM и LPT)
- **Linux:** `minicom -b 115200 -D /dev/ttyUSB0`
- **macOS:** `screen /dev/tty.usbserial-XXXX 115200`

Проверь соединение — отправь:
```
AT
```
Должен прийти ответ: `OK`

Если нет ответа — поменяй TX/RX местами, это частая ошибка.

### 4.3 Последовательность AT-команд (выполняй строго по порядку)

```
AT+I2SCFG=3
```
Жди: `OK`
Смысл: переводим I2S в режим slave, 48 кГц base clock, 16-bit, стандартный I2S формат.

```
AT+HFPSR=16000
```
Жди: `OK`
Смысл: устанавливаем частоту HFP голосового канала 16 кГц (совпадает с прошивкой ESP32).

```
AT+REBOOT
```
Модуль перезагрузится. После перезагрузки он готов к работе.

> **Не трогай AT+PROFILE.** Заводское значение `+PROFILE=1195` уже включает все нужные профили: SPP + GATT + **HFP-HF** + A2DP Sink + AVRCP + PBAP. Если отправить `AT+PROFILE=1` — это оставит только SPP (BIT[0]=1) и отключит HFP. Телефон не сможет подключиться для звонков.

### Таблица битов AT+PROFILE (справочно)

| Бит | Профиль |
|-----|---------|
| BIT[0] | SPP |
| BIT[1] | GATT Server |
| BIT[2] | GATT Client |
| **BIT[3]** | **HFP-HF** ← нужен для звонков |
| BIT[4] | HFP-AG |
| BIT[5] | A2DP Sink |
| BIT[6] | A2DP Source |
| BIT[7] | AVRCP Controller |
| BIT[8] | AVRCP Target |
| BIT[9] | HID Keyboard |
| BIT[10] | PBAP Server |
| BIT[15] | iAP2 |

Заводское значение 1195 = 1+2+8+32+128+1024 = SPP+GATT+HFP-HF+A2DP+AVRCP+PBAP.

### 4.4 Проверь настройки после перезагрузки

```
AT+I2SCFG?
```
Ответ должен быть: `+I2SCFG=3`

```
AT+HFPSR?
```
Ответ должен быть: `+HFPSR=16000`

```
AT+PROFILE?
```
Ответ должен быть: `+PROFILE=1195`

Также в статусе после ребута должна появиться строка `+HFPSTAT=1` — это подтверждает что HFP активен и ждёт подключения телефона.

### Восстановление если AT+PROFILE был сломан

Если ты уже отправил `AT+PROFILE=1` (только SPP), восстанови командами:

```
AT+PROFILE=1195
```
```
AT+REBOOT
```

После ребута проверь наличие `+HFPSTAT=1` в статусе.

## 5. Шаг 3 — Подключение проводов

После настройки AT-команд **отключи USB-UART адаптер** и подключи I2S линии к ESP32-S3.

### Полная схема подключения

```
FSC-BT1036x          ESP32-S3 Dev Board
───────────          ──────────────────
  P30 (BCLK)  ──────►  GPIO 4
  P31 (WS)    ──────►  GPIO 5
  P33 (DO)    ──────►  GPIO 6   ← аудио данные: модуль → ESP
  P32 (DI)    —— NC             (в v0.1 не используется)
  P24 (MCLK)  —— NC             (не нужен в slave режиме)
  GND         ──────── GND
  VDD         ──────── 3.3V

  P0 (UART_TX)──────►  любой GPIO для мониторинга (опционально)
  P1 (UART_RX) —— NC  (AT-команды уже настроены)
  P15 (RESET) ── 10kΩ ── 3.3V
```

### Визуально (упрощённо)

```
                ┌────────────────────┐
                │    FSC-BT1036x     │
                │                    │
   3.3V ─────── │ VDD            P30 │ ──────── GPIO 4 (BCLK)
   GND ──────── │ GND            P31 │ ──────── GPIO 5 (WS)
   3.3V─[10kΩ]─ │ P15 (RST)     P33 │ ──────── GPIO 6 (DIN)
                │                    │
                └────────────────────┘

                ┌────────────────────┐
                │     ESP32-S3       │
                │                    │
                │ GPIO4  (BCLK) ◄─── │
                │ GPIO5  (WS)   ◄─── │
                │ GPIO6  (DIN)  ◄─── │
                │ 3.3V              │
                │ GND               │
                └────────────────────┘
```

> **Важно:** I2S линии — короткие провода, желательно не длиннее 10–15 см. Длинные провода добавляют ёмкость и могут искажать BCLK.

## 6. Шаг 4 — Первый запуск и проверка

### 6.1 Запусти монитор ESP32

```bash
idf.py monitor
```

Или подключись любым Serial Monitor (115200 baud) к порту ESP32.

Ожидаемые сообщения при старте:
```
I (xxx) audio_stream: connected to AP
I (xxx) audio_stream: got ip:192.168.1.XXX
```

### 6.2 Сопряги телефон с BT1036

- Включи Bluetooth на телефоне
- Найди устройство с именем вида `FSC-BT1036-XXXX`
- Нажми "Подключить" / "Pair"
- Подтверди сопряжение если потребуется

После сопряжения модуль должен появиться в телефоне как **Bluetooth-гарнитура / Car Kit**.

## 7. Шаг 5 — Совершаем тестовый звонок

1. На телефоне соверши или прими звонок.
2. Убедись что вызов маршрутизирован через BT-гарнитуру (в телефоне должен появиться значок гарнитуры).
3. На BT1036 активируется I2S поток — модуль начнёт выдавать PCM аудио на P33 (DO).

В мониторе ESP32 ты должен увидеть непрерывное чтение I2S без ошибок. Если появляется:
```
W (xxx) audio_stream: Ring buffer full, dropping audio frame
```
Это означает что ПК не успевает принимать UDP — запусти `udp_capture.py` до звонка (см. Шаг 6).

## 8. Шаг 6 — Принимаем аудио на ПК

### 8.1 Требования

- Python 3.8+
- Стандартные библиотеки (`socket`, `wave`, `argparse`) — ничего устанавливать не нужно

### 8.2 Запусти скрипт **до** звонка

```bash
python scripts/udp_capture.py --port 5004 --outfile call.wav
```

Ожидаемый вывод:
```
Listening on 0.0.0.0:5004 -> writing to call.wav
```

Как только ESP32 начнёт слать UDP, появятся строки:
```
100 packets, 64000 bytes, 25.6 kbps
200 packets, 128000 bytes, 25.6 kbps
...
```

### 8.3 Останови запись

Нажми **Ctrl+C** для остановки. Скрипт закроет WAV файл:
```
Stopped.
Packets: 350
Bytes: 224000
Duration: 7.0s
Avg bitrate: 256.0 kbps
```

Открой `call.wav` в любом плеере (VLC, Audacity, Windows Media Player).

### 8.4 Параметры скрипта

```
--bind    IP адрес для приёма (по умолчанию: 0.0.0.0 = все интерфейсы)
--port    UDP порт (по умолчанию: 5004)
--outfile имя выходного WAV файла (по умолчанию: received.wav)
--rate    частота дискретизации (по умолчанию: 16000)
--channels количество каналов (по умолчанию: 1 = моно)
--width   байт на сэмпл (по умолчанию: 2 = 16-bit)
```

Пример с явными параметрами:
```bash
python scripts/udp_capture.py --bind 192.168.1.50 --port 5004 --outfile test_call.wav --rate 16000 --channels 1 --width 2
```

## 9. Диагностика проблем

### "ESP32 не видит Wi-Fi / failed to connect to AP"
- Проверь `WIFI_SSID` и `WIFI_PASS` в `main.c` — они чувствительны к регистру
- ESP32-S3 работает только с 2.4 GHz, не 5 GHz
- Убедись что роутер не скрывает SSID

### "AT команды не работают / нет ответа"
- Поменяй TX/RX местами (частая ошибка)
- Проверь питание: VDD должен быть 3.3V, не 5V
- Проверь что P15 (RESET) подтянут к 3.3V через 10 кОм
- Убедись что скорость терминала 115200, без flow control

### "Телефон не видит BT1036"
- После `AT+REBOOT` модуль должен быть в режиме паринга
- Попробуй отправить `AT+BTNAME?` чтобы узнать имя устройства
- Удали старые сопряжения с обоих устройств и попробуй снова

### "В WAV файле тишина или шум"
- Убедись что звонок маршрутизирован через BT-гарнитуру (не через динамик телефона)
- Проверь правильность подключения P33 (DO) → GPIO 6
- Проверь что `AT+HFPSR=16000` был принят (ответ `OK`, не `ERROR`)
- В мониторе ESP32 не должно быть `i2s read err=...`

### "UDP пакеты не доходят до ПК"
- Убедись что ESP32 и ПК в одной локальной сети
- Проверь firewall: разреши входящий UDP на порт 5004
  - **Windows:** Брандмауэр → Входящие правила → Новое правило → Порт → UDP → 5004
  - **Linux:** `sudo ufw allow 5004/udp`
- Пропингуй IP ПК с другого устройства в сети чтобы убедиться что IP верный

### "Ring buffer full, dropping audio frame"
- Запускай `udp_capture.py` **до** того как начнётся звонок
- Убедись что ПК не занят тяжёлыми задачами
- Это не критично для проверки — небольшие дропы допустимы

## 10. Приложение: полная таблица GPIO и пинов

### ESP32-S3 → FSC-BT1036 I2S

| ESP32-S3 GPIO | Сигнал | FSC-BT1036 Pin | Направление |
|---------------|--------|----------------|-------------|
| GPIO 4 | I2S_BCLK | P30 | ESP → BT1036 |
| GPIO 5 | I2S_WS | P31 | ESP → BT1036 |
| GPIO 6 | I2S_DIN | P33 (DO) | BT1036 → ESP |
| NC | I2S_DOUT | P32 (DI) | ESP → BT1036 (v0.2+) |
| NC | I2S_MCLK | P24 | NC (не нужен в slave) |
| GND | GND | GND | — |
| 3.3V | Power | VDD | — |

### FSC-BT1036 UART (только для AT-команд)

| FSC-BT1036 Pin | Сигнал | USB-UART адаптер |
|----------------|--------|-----------------|
| P0 | UART_TX | RX |
| P1 | UART_RX | TX |
| GND | GND | GND |
| VDD | 3.3V | 3.3V |
| P15 | RESET | 3.3V через 10 кОм |

### Параметры I2S прошивки

| Параметр | Значение |
|----------|----------|
| Режим ESP32 | I2S Master |
| Режим BT1036 | I2S Slave (AT+I2SCFG=3) |
| Частота дискретизации | 16 000 Гц |
| Разрядность | 16 бит |
| Каналы | Моно |
| Размер фрейма | 20 мс = 320 сэмплов = 640 байт |
| UDP порт | 5004 |

### Быстрый чеклист запуска

```
[ ] WIFI_SSID и WIFI_PASS исправлены в main.c
[ ] UDP_REMOTE_IP указывает на реальный IP ПК
[ ] idf.py flash завершился без ошибок
[ ] BT1036 настроен AT-командами (I2SCFG=3, HFPSR=16000, PROFILE=1, REBOOT)
[ ] Провода подключены: P30→GPIO4, P31→GPIO5, P33→GPIO6, GND-GND, VDD-3.3V
[ ] P15 подтянут к 3.3V через 10 кОм
[ ] ESP32 подключился к Wi-Fi (видно в monitor)
[ ] udp_capture.py запущен на ПК
[ ] Телефон спарен с BT1036
[ ] Звонок маршрутизирован через BT-гарнитуру
[ ] call.wav содержит голос
```
