# OpenVoiceBridge v0.2 — Туториал: два модуля FSC-BT1036x

> **Цель:** телефонный звонок поступает на BT1036-A → ESP32-S3 → BT1036-B → BT-наушники.
> Микрофон наушников идёт обратно в телефон через ту же цепочку.
> UDP-стриминг на ПК продолжает работать параллельно.

## 1. Архитектура системы

```
                  BT HFP-HF                I2S0 (full-duplex)
  Телефон ◄──────────────────► BT1036-A ◄──────────────────► ESP32-S3
  (Android)                  (phone side)    GPIO 4/5/6/7        │
                                                                  │ I2S1 (full-duplex)
                                                                  │ GPIO 15/16/17/18
                                                                  │
                  BT HFP-AG                                       ▼
  Наушники ◄──────────────────► BT1036-B ◄──────────────────────►
  (BT headset)               (headset side)          UDP/Wi-Fi
                                                          │
                                                          ▼
                                                          ПК (call.wav)
```

**Потоки аудио:**

| Путь | Откуда | Куда |
|------|--------|------|
| Звонок (воспроизведение) | BT1036-A P33 → GPIO6 → I2S0 RX | → UDP → ПК<br>→ I2S1 TX → GPIO17 → BT1036-B → наушники |
| Микрофон (передача) | Наушники → BT1036-B P33 → GPIO18 → I2S1 RX | → I2S0 TX → GPIO7 → BT1036-A P32 → телефон |

**Роли модулей:**

| Модуль | BT-роль | I2S-роль |
|--------|---------|----------|
| BT1036-A | HFP-HF (Hands-Free) — притворяется BT-гарнитурой для телефона | I2S Slave, ESP32 генерирует клок |
| BT1036-B | HFP-AG (Audio Gateway) — притворяется телефоном для наушников | I2S Slave, ESP32 генерирует клок |
| ESP32-S3 | Wi-Fi STA + I2S Master (оба порта) | Ретранслятор аудио |

## 2. Что понадобится

| Компонент | Кол-во | Примечание |
|-----------|--------|------------|
| FSC-BT1036x (Feasycom) | **2 шт** | оба одинаковые, прошивка V2.8.7+ |
| ESP32-S3-DevKitC-1 v1.1 | 1 шт | или любой ESP32-S3 |
| USB-UART адаптер (3.3V) | 1 шт | CP2102, CH340, FT232 — для AT-команд |
| Провода Dupont / макетка | — | I2S линии желательно ≤ 15 см |
| Резистор 10 кОм | 2 шт | подтяжка P15 (RESET) каждого модуля |
| Телефон | 1 шт | Android с BT |

> Настраиваем по одному модулю — подключи → настрой → переключи на второй.

## 3. Схема подключения проводов

### BT1036-A → ESP32-S3 (I2S0, сторона телефона)

```
FSC-BT1036-A             ESP32-S3-DevKitC-1 v1.1
────────────             ──────────────────────────
  VDD         ────────── 3.3V
  GND         ────────── GND
  P15 (RST)   ──[10kΩ]── 3.3V
  P30 (BCLK)  ─────────► GPIO 4
  P31 (WS)    ─────────► GPIO 5
  P33 (DO)    ─────────► GPIO 6   ← звонок с телефона → ESP (RX)
  P32 (DI)    ◄───────── GPIO 7   ← микрофон с наушников → телефон (TX)
```

### BT1036-B → ESP32-S3 (I2S1, сторона наушников)

```
FSC-BT1036-B             ESP32-S3-DevKitC-1 v1.1
────────────             ──────────────────────────
  VDD         ────────── 3.3V
  GND         ────────── GND
  P15 (RST)   ──[10kΩ]── 3.3V
  P30 (BCLK)  ─────────► GPIO 15
  P31 (WS)    ─────────► GPIO 16
  P32 (DI)    ◄───────── GPIO 17  ← звонок → наушники (TX)
  P33 (DO)    ─────────► GPIO 18  ← микрофон наушников → телефон (RX)
```

### Визуальная схема

```
          ┌──────────────┐      I2S0      ┌──────────────────────┐
Телефон ◄─┤  BT1036-A    ├────────────────┤                      ├──── Wi-Fi UDP ──► ПК
   BT HFP │  (HFP-HF)   │  4,5,6,7       │     ESP32-S3         │
          └──────────────┘                │                      │
                                          │  I2S master (оба)    │
          ┌──────────────┐      I2S1      │                      │
Наушники ◄┤  BT1036-B    ├────────────────┤                      │
   BT HFP │  (HFP-AG)   │  15,16,17,18   └──────────────────────┘
          └──────────────┘
```

> **Примечание:** UART пины (P0/P1) BT1036 используются только при настройке через USB-UART.
> В рабочем режиме они не подключены к ESP32.

## 4. Шаг 1 — Настройка BT1036-A (сторона телефона)

Это **одноразовая** настройка. BT1036-A работает как стандартная HFP-HF гарнитура.

### 4.1 Подключи BT1036-A к USB-UART адаптеру

```
USB-UART адаптер        BT1036-A
────────────────        ────────
TX              ──────► P1 (UART_RX)
RX              ◄────── P0 (UART_TX)
GND             ─────── GND
3.3V            ─────── VDD
3.3V ──[10kΩ]──────── P15 (RESET)
```

Настройки терминала: **115200 baud, 8N1, no flow control**

### 4.2 Проверь связь

```
AT
```
→ `OK`

Если нет ответа: поменяй TX/RX местами.

### 4.3 Проверь текущий профиль

```
AT+PROFILE?
```
→ `+PROFILE=1195`

1195 = SPP + GATT Server + HFP-HF + A2DP Sink + AVRCP + PBAP — **это правильно, не меняй.**

> ⚠️ **Не отправляй AT+PROFILE с другим значением для BT1036-A.**
> BIT[3] (HFP-HF) должен быть включён — именно он позволяет телефону видеть модуль как гарнитуру.

### 4.4 Настрой I2S и частоту дискретизации

```
AT+I2SCFG=3
```
→ `OK`

```
AT+HFPSR=8000
```
→ `OK`

> **Почему 8000?** OnePlus 13R договаривается до CVSD (8 кГц), не mSBC. Если твой телефон
> поддерживает mSBC, можно попробовать 16000. Реальное значение придёт в `+HFPSR=` во время звонка.

```
AT+REBOOT
```

Модуль перезагрузится. После перезагрузки должна появиться строка `+HFPSTAT=1`.

### 4.5 Верификация

```
AT+I2SCFG?    → +I2SCFG=3    ✓
AT+HFPSR?     → +HFPSR=8000  ✓
AT+PROFILE?   → +PROFILE=1195 ✓
```

## 5. Шаг 2 — Настройка BT1036-B (сторона наушников)

BT1036-B должен работать в роли **HFP-AG (Audio Gateway)** — он притворяется "телефоном"
для наушников. Наушники подключатся к нему как к гарнитуре (HFP-HF).

### 5.1 Переключи USB-UART на BT1036-B

Те же провода, та же схема. Убедись что BT1036-A отключён или не мешает.

### 5.2 Проверь связь

```
AT
```
→ `OK`

### 5.3 Установи профиль HFP-AG + A2DP Source

```
AT+PROFILE=83
```
→ `OK`

83 = 1 (SPP) + 2 (GATT Server) + 16 (HFP-AG) + 64 (A2DP Source)

> **Почему именно это?**
> - HFP-AG (BIT[4]=16) — наушники подключаются к нему как к телефону, получают двусторонний звук
> - A2DP Source (BIT[6]=64) — альтернативный путь воспроизведения (резервный)
> - HFP-HF и HFP-AG **взаимоисключающие** — нельзя включить оба одновременно
> - BT1036-A использует HFP-HF (дефолт), BT1036-B должен использовать HFP-AG

### 5.4 Настрой I2S

```
AT+I2SCFG=3
```
→ `OK`

```
AT+HFPSR=8000
```
→ `OK`

### 5.5 Включи автоподключение

```
AT+AUTOCONN=83
```
→ `OK`

После сопряжения с наушниками модуль будет автоматически переподключаться при включении.

```
AT+REBOOT
```

### 5.6 Верификация

```
AT+I2SCFG?    → +I2SCFG=3  ✓
AT+HFPSR?     → +HFPSR=8000 ✓
AT+PROFILE?   → +PROFILE=83  ✓
```

## 6. Шаг 3 — Прошивка ESP32-S3

### 6.1 Отредактируй `main/main.c`

```c
#define WIFI_SSID       "имя_твоей_сети"
#define WIFI_PASS       "пароль_сети"
#define UDP_REMOTE_IP   "192.168.1.214"   // IP твоего ПК
#define SAMPLE_RATE_HZ  (8000)            // должно совпадать с AT+HFPSR обоих модулей
```

Узнать IP ПК:
- **Windows:** `ipconfig` → IPv4 Address
- **Linux/macOS:** `ip addr` или `ifconfig`

### 6.2 Подключи ESP32-S3 через UART-разъём

Подключай кабель в разъём с маркировкой **`UART`** (правый, ближе к надписи UART).
Это идёт через CP2102N → виден как COM-порт.

### 6.3 Собери и прошей

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COM3 flash monitor        # Windows
idf.py -p /dev/ttyUSB0 flash monitor  # Linux
```

После прошивки в мониторе должно появиться:
```
I (xxx) audio_stream: connected to AP
I (xxx) audio_stream: got ip:192.168.1.XXX
```

Для выхода из монитора: **Ctrl+]**

## 7. Шаг 4 — Сопряжение BT1036-A с телефоном

> Это делается один раз. BT1036-A уже настроен и перезагружен.

1. **Убедись что BT1036-A включён** (питание подключено, P15 подтянут)
2. После загрузки в терминале BT1036-A появится:
   ```
   +HFPSTAT=1
   ```
   Это значит HFP активен и ждёт телефон.

3. На **телефоне** включи Bluetooth → "Найти новые устройства"
4. Найди `FSC-BT1036-XXXX` в списке
5. Нажми "Подключить" / "Pair"
6. Подтверди сопряжение если потребуется

После сопряжения в терминале BT1036-A:
```
+HFPSTAT=3       ← HFP standby, телефон подключён
+HFPDEV=...      ← информация о телефоне
```

> **Если телефон уже был спарен раньше** (v0.1 тест) — пересопрягать не нужно.
> Просто убедись что BT1036-A подключён к телефону (значок гарнитуры в строке статуса).

## 8. Шаг 5 — Сопряжение BT1036-B с наушниками

> BT1036-B должен работать как "телефон" для наушников. Наушники подключатся к нему первыми.

### 8.1 Переведи наушники в режим сопряжения

Большинство BT-наушников: **зажми кнопку питания 3–5 секунд** пока не услышишь "pairing mode"
или не замигает синий светодиод быстро.

### 8.2 Сосканируй наушники с BT1036-B

В терминале BT1036-B отправь:

```
AT+SCAN=1
```

Подожди 10–15 секунд. Придут строки вида:
```
+SCAN=1C:5C:F2:26:D7:73,HFP+A2DP,SonyWH1000XM4
+SCAN=A8:32:00:11:22:33,HFP,JBLLive650
+SCAN=0    ← конец сканирования
```

Формат: `+SCAN=MAC,профили,имя`

Запомни MAC своих наушников (12 символов без двоеточий).

### 8.3 Подключись к наушникам по HFP

```
AT+HFPCONN=1C5CF226D773
```
(замени на MAC своих наушников)

→ `OK`

Через 1–3 секунды придут события:
```
+HFPSTAT=3     ← HFP подключён к наушникам
+HFPDEV=...    ← информация о наушниках
```

Наушники должны издать звуковой сигнал "подключено".

> **Если наушники поддерживают только A2DP** (некоторые игровые модели без микрофона):
>
> ```
> AT+A2DPCONN=1C5CF226D773
> ```
>
> В этом случае **микрофонный путь работать не будет** — только воспроизведение.

### 8.4 Сохрани сопряжение

После успешного подключения сопряжение сохраняется автоматически.
При следующем включении — `AT+AUTOCONN=83` гарантирует автоматическое подключение.

Можешь проверить список сопряжений:
```
AT+PLIST
```

## 9. Шаг 6 — Последовательность запуска

После первоначальной настройки каждый запуск выглядит так:

### Порядок включения

```
1. Включи ESP32-S3 (USB питание)
   → ESP32 подключается к Wi-Fi

2. Включи BT1036-A
   → Автоматически подключается к телефону (если телефон рядом)
   → +HFPSTAT=3 в терминале BT1036-A

3. Включи BT1036-B
   → Автоматически подключается к наушникам (AT+AUTOCONN)
   → +HFPSTAT=3 в терминале BT1036-B

4. Убедись что ESP32 уже видит I2S (нет ошибок в мониторе)

5. На ПК запусти захват UDP:
   python scripts/udp_capture.py --port 5004 --rate 8000 --outfile call.wav

6. Соверши звонок с телефона или позвони на телефон
```

> **Важно:** ESP32 нужно включить **до** модулей, так как он является I2S мастером.
> Если BT1036 включить раньше — он не найдёт BCLK и может зависнуть.
> На практике порядок гибкий, но при проблемах с I2S — перезагружай модули после ESP32.

## 10. Ожидаемые события в терминале

### BT1036-A (телефонная сторона) — при входящем звонке

```
+HFPSTAT=5,+79001234567   ← входящий звонок, номер АОН
+HFPRING=1                ← звонит
+HFPIBR=1                 ← inband ring (звук звонка через I2S)
+HFPAUDIO=1               ← I2S активен, аудио идёт ◄── КЛЮЧЕВОЕ
+HFPSR=8000               ← подтверждение rate от телефона
+HFPSTAT=6                ← звонок активен
+HFPSTAT=6,+79001234567
...
+HFPAUDIO=0               ← звонок завершён, I2S остановлен
+HFPSTAT=3                ← HFP standby
```

Если `+HFPAUDIO=1` не появляется → аудио осталось на телефоне.
Принудительно переключить: `AT+HFPADTS=2`

### BT1036-B (сторона наушников) — при активном звонке

```
+HFPSTAT=6                ← HFP-AG видит активную сессию
+HFPAUDIO=1               ← I2S к наушникам активен
```

### ESP32-S3 (idf.py monitor) — при звонке

```
I (xxx) audio_stream: call frame=50 mono_bytes=320 max=2341 <<< AUDIO
I (xxx) audio_stream: hp_tx frame=50 written=640 max=2341
I (xxx) audio_stream: call frame=100 mono_bytes=320 max=1876 <<< AUDIO
```

Если `max=0` или `(silence)` — звук есть, но тихо, или `+HFPAUDIO=1` не пришло.

## 11. Диагностика проблем

### BT1036-A не подключается к телефону

- Убедись что `AT+PROFILE?` → `+PROFILE=1195` (BIT[3]=HFP-HF включён)
- Убедись что в статусе есть `+HFPSTAT=1`
- Удали старое сопряжение с телефона и попробуй снова
- Попробуй `AT+PAIR=1` (перевести в режим пейринга вручную)

### Наушники не подключаются к BT1036-B

- Проверь `AT+PROFILE?` → должно быть `+PROFILE=83`
- Убедись что наушники действительно в режиме пейринга (мигают быстро)
- Попробуй `AT+SCAN=1` — если наушники не видны, они не в режиме пейринга
- Некоторые наушники требуют удалить предыдущие сопряжения: на наушниках обычно "зажать обе кнопки 10 сек"

### Звук есть в UDP/WAV, но не слышен в наушниках

- Проверь что BT1036-B соединён с наушниками: `AT+HFPSTAT?` → `+HFPSTAT=3` или выше
- Проверь что I2S1 инициализировался без ошибок (в ESP32 мониторе нет `E (xxx) i2s...`)
- Возможно SCO-канал не открылся: попробуй `AT+HFPADTS=2` на BT1036-B при активном звонке
- Проверь провода: GPIO17 → BT1036-B P32 (DI), GPIO15 → P30 (BCLK), GPIO16 → P31 (WS)

### Звук в наушниках есть, но микрофон не работает (телефон не слышит голос)

- Убедись что GPIO18 подключён к BT1036-B P33 (DO)
- В ESP32 мониторе найди задачу `mic_rx` — она должна читать данные
- Проверь `AT+HFPSTAT?` на BT1036-B — нужен `+HFPSTAT=6` (активный звонок) для SCO mic
- Если наушники подключены только через A2DP (а не HFP) — микрофон недоступен

### ESP32 не стартует I2S / вылетает при инициализации

- Убедись что оба BT1036 включены и **P15 подтянуты к 3.3V через 10 кОм**
- BT1036 без подтяжки P15 может шуметь на I2S линиях и мешать инициализации
- Попробуй инициализировать ESP32 без подключённых модулей — если работает, проблема в проводах
- Проверь нет ли конфликта GPIO: убедись что пины 4,5,6,7,15,16,17,18 не заняты другим

### Задержка звука / прерывания

- Это ожидаемо: два I2S + Wi-Fi + кольцевые буферы = ~40–100 мс задержки
- Уменьшить: снизить `RINGBUF_CAPACITY_BYTES` (по умолчанию 50 фреймов × 320 байт)
- Если слышны щелчки — увеличить буфер (контрмера потере фреймов)

### `s_rb_tx full, dropping frame` или `s_rb_mic full, dropping frame`

- Задача `i2s_tx_task` или `mic_tx_task` не успевает писать в I2S
- Убедись что BT1036-B подключён и I2S1 инициализирован
- BT1036-B без активного BT-соединения с наушниками может не принимать I2S данные

## 12. Быстрый чеклист

### Первоначальная настройка (один раз)

```
BT1036-A:
[ ] AT+I2SCFG=3           → OK
[ ] AT+HFPSR=8000         → OK
[ ] AT+PROFILE?           → +PROFILE=1195  (не менять)
[ ] AT+REBOOT
[ ] После ребута: +HFPSTAT=1 появляется ✓

BT1036-B:
[ ] AT+PROFILE=83         → OK
[ ] AT+I2SCFG=3           → OK
[ ] AT+HFPSR=8000         → OK
[ ] AT+AUTOCONN=83        → OK

## Приложение: таблица AT-команд BT1036-B (шпаргалка)

| Команда | Что делает |
|---------|-----------|
| `AT+PROFILE=83` | Установить HFP-AG + A2DP Source профиль |
| `AT+SCAN=1` | Сканировать BR/EDR устройства 12.8 сек |
| `AT+SCAN=1,10,Sony` | Сканировать 12.8 сек, фильтр по имени "Sony" |
| `AT+SCAN=0` | Остановить сканирование |
| `AT+HFPCONN=MAC` | Подключиться к наушникам по HFP |
| `AT+HFPCONN` | Переподключиться к последним наушникам |
| `AT+HFPDISC` | Разорвать HFP соединение |
| `AT+HFPSTAT?` | Состояние HFP (1=idle, 3=connected, 6=call active) |
| `AT+A2DPCONN=MAC` | Подключиться по A2DP (только воспроизведение) |
| `AT+HFPADTS=2` | Перенаправить аудио на наушники принудительно |
| `AT+PLIST` | Список сопряжённых устройств |
| `AT+PLIST=<idx>,0` | Удалить устройство из списка |
| `AT+AUTOCONN=83` | Автоподключение по HFP-AG и A2DP Source |
| `AT+AUTOCONN=0` | Отключить автоподключение |
| `AT+RESTORE` | Сброс к заводским настройкам (всё слетит) |

## Приложение: биты AT+PROFILE

| Бит | Значение | Профиль |
|-----|----------|---------|
| BIT[0] | 1 | SPP |
| BIT[1] | 2 | GATT Server |
| BIT[2] | 4 | GATT Client |
| BIT[3] | 8 | **HFP-HF** (гарнитура) — для BT1036-A |
| BIT[4] | 16 | **HFP-AG** (телефон/шлюз) — для BT1036-B |
| BIT[5] | 32 | A2DP Sink (приёмник музыки) |
| BIT[6] | 64 | **A2DP Source** (источник музыки) — для BT1036-B |
| BIT[7] | 128 | AVRCP Controller |
| BIT[8] | 256 | AVRCP Target |
| BIT[9] | 512 | HID Keyboard |
| BIT[10] | 1024 | PBAP Server |
| BIT[15] | 32768 | iAP2 |

> HFP-HF и HFP-AG **взаимоисключающие**.
> A2DP Sink и A2DP Source **взаимоисключающие**.
> AVRCP Controller и AVRCP Target **взаимоисключающие**.

BT1036-A = 1+2+8+32+128+1024 = **1195** (заводской)
BT1036-B = 1+2+16+64 = **83**
