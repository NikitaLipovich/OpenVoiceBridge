# Тестовый звонок: запись и качество

Одна команда готовит стенд, ждёт ваш звонок, пишет оба направления разговора и говорит, как прошло.
Сама ничего не набирает и звук на ПК не включает.

## 1. Что включить

- Коробка с LyraT и S3 включена (аккумуляторы), прошло 30 с.
- ПК в той же сети Wi-Fi, что и платы.
- Телефон: Bluetooth включён, LyraT_Phone подключена. USB-кабель телефона не обязателен.

## 2. Команда

Из папки репозитория:

```
python lyrat_resend/tools/bench/call_check.py
```

## 3. Что увидеть

Сначала проверки, каждая строкой `[ок]` или `[НЕТ]` с тем, что сделать:

```
  [ок] S3 отвечает по Wi-Fi
  [ок] версии: S3 ..., LyraT ...
  [ок] LyraT жива ...
  [ок] телефон подключён к LyraT_Phone (HFP)
  [ок] поток S3 включён (TAP1): идут обе линии
  [ок] часы S3 и ПК сведены: ...
```

`[--]` — предупреждение, звонить можно. При `[НЕТ]` команда завершается: исправьте и запустите снова.

Затем **ЗВОНИТЕ**.

## 4. Как позвонить

Наберите номер с телефона (или примите звонок). Звук должен идти через гарнитуру LyraT_Phone: если телефон
перевёл его на динамик, выберите LyraT_Phone в меню звука во время звонка. Говорите как обычно.

Во время разговора раз в секунду обновляется строка:

```
00:42 канал открыт | вниз -23.1 дБ ######...... | вверх -38.0 дБ ###......... | потеряно 0/0 пак. | обрывов 0 | задержка 43 мс
```

вниз — собеседник, вверх — ваш микрофон, потеряно — пакеты S3 → ПК, обрывов — разрывы канала гарнитуры,
связи с телефоном и потока.

Положите трубку. Запись остановится сама через 10 с (или Enter, или Ctrl+C).

## 5. Где файлы

`goals_harness/bench_runs/calls/<дата-время>/` (вне git):

| Файл | Что в нём |
|---|---|
| `<время>_down.wav` | собеседник: то, что телефон шлёт в наушники |
| `<время>_up.wav` | ваш микрофон: линия кодека до обработки платы |
| `<время>_both.wav` | оба: слева собеседник, справа вы, выровнены по времени |
| `report.md` | отчёт (и `report.json` с теми же числами) |

Слушайте своим плеером. Записи с чужим голосом удаляйте сами, когда они не нужны.

## 6. Как читать отчёт

Первая строка — итог: `качество: норм` или `качество: есть проблемы: ...` с перечнем.

| Строка | Норма |
|---|---|
| кодек | mSBC (CVSD — узкая полоса) |
| уровень в речи | от −40 до −6 дБFS |
| речь над фоном | 15 дБ и больше |
| выпадения звука | не больше 6 в минуту |
| клиппинг | до 0,1 % |
| потери S3 → ПК | до 2 % |
| обрывы, перезагрузки | 0 |
| задержка живого потока | до 300 мс (на стенде около 45 мс) |

`up` записан до шумоподавления платы и до Bluetooth: собеседник слышит обработанный звук, и обрывы в сторону
телефона в этой записи не видны.

## 7. Типовые проблемы

| Видите | Сделайте |
|---|---|
| `[НЕТ] S3 не отвечает по Wi-Fi` | включите коробку, подождите 30 с; проверьте, что ПК в той же сети |
| `[НЕТ] телефон НЕ подключён к LyraT_Phone` | телефон: Bluetooth → LyraT_Phone → подключить; запустите снова |
| `[НЕТ] нет потока с S3` | брандмауэр Windows должен пускать python на UDP 5004–5006 |
| `[--] фон микрофона ...` | шум на линии микрофона (#005): подождите пару минут, запустите снова |
| `жду начала разговора` и ничего | звонок идёт на динамик телефона: выберите LyraT_Phone в меню звука |
| `канал гарнитуры (SCO) не открывался` | то же; итог «не проверено», файлы без разговора |
| `стенд занят другой программой` | идёт другой прогон; дождитесь конца |

## Для разработчиков

- Живой поток для будущей транскрибации: пока команда работает, выровненный стерео-поток идёт на
  `127.0.0.1:5010` (формат `callpcm` v1 в `tools/bench/call_stream.py`). Пример потребителя:
  `python lyrat_resend/tools/bench/call_stream.py listen --seconds 30 --wav out.wav`. Выключить: `--no-pcm`.
- Прогон без звонка (R3): `call_check.py --probe 3` (по 20 с, `--seconds` меняет) — канал открывает приложение sco_probe, телефон
  играет тоны, LyraT на `vol 0`. Если на телефон придёт настоящий звонок, прогон останавливается и его звук удаляется.
- Тесты: `python lyrat_resend/tools/run_tests.py --only call_check`.
