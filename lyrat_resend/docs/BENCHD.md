# Служба стенда benchd

`benchd` — один процесс на ПК, который держит связь с S3 и **непрерывно** пишет лог обеих плат, строит из него индекс
событий, даёт гоалам HTTP/JSON API и CLI (`bench.py`), сериализует доступ к стенду замком и показывает владельцу
веб-страницу. Прошивка не меняется: служба говорит с S3 тем же протоколом, что и инструменты (лог — UDP 5008, команды —
реле 5006, `docs/OTA.md` «Debug log», `docs/S3_UART.md`). Сделано гоалом 103.

Зачем: раньше лог писался только пока запущен инструмент (строки загрузки и отключение стенда терялись), каждый инструмент
искал S3 широковещанием, а «стенд занят» определялся по списку процессов. S3 отдаёт лог **одному** слушателю —
последнему спросившему; два инструмента отбирали лог друг у друга. Теперь слушатель один — служба, остальные берут лог у
неё.

## Запуск

```
python lyrat_resend/tools/bench/benchd.py
```

Печатает строку JSON (pid, порты, адрес страницы) и работает до Ctrl+C. Адрес S3: `--host`, иначе `BENCH_S3_ADDR`, иначе
поиск широковещанием (как у `s3_uart.py`); если S3 замолчала на 30 с — ищет заново (DHCP мог сменить адрес). Второй
экземпляр не стартует (`benchd already runs`).

Основные параметры (все — `benchd.py --help`):

| Параметр | По умолчанию | Что |
|---|---|---|
| `--http-port` | 5080 | API и страница (127.0.0.1) |
| `--relay-port` | 5081 | реле лога для инструментов (127.0.0.1) |
| `--lan` | выкл | слушать все интерфейсы: страница и чтение из локальной сети |
| `--lan-control` | выкл | вместе с `--lan`: управление из сети — только с токеном (`X-Bench-Token`, гоал 104) |
| `--discovery-port` | 5082 | с `--lan`: UDP-ответ на «BENCHD?» — телефон находит ПК сам |
| `--rotate-mb`, `--rotate-min` | 20, 60 | новый файл лога по размеру и по времени (и в полночь) |
| `--disk-mb` | 2048 | общий предел файлов лога; старейшие удаляются, события остаются |
| `--lost-s` | 10 | плата «пропала», если столько секунд нет признаков жизни |
| `--bod-poll-s` | 300 | спрашивать LyraT `bod` (просадки питания) так часто, **только пока замок свободен**; 0 — выкл |
| `--bt-mode-cmd` | нет | команда консоли для кнопки «Режим BT», `{mode}` подставляется (в `phone-bringup` такой команды нет — кнопка скрыта) |
| `--home` | `BENCHD_HOME` или `goals_harness/bench_runs/benchd` | где лежат логи, события, состояние замка |

Все порты сдвигаются переменной `BENCH_PORT_OFFSET` (см. «Порты» ниже). На настоящем стенде офсет 0.

## Что лежит на диске

`goals_harness/bench_runs/benchd/` (вне git, R6):

- `<ГГГГ-ММ-ДД>/log-ЧЧММСС.txt` — строки `<время ПК ISO, мс> <плата> <время платы, с> <текст>`, MAC скрыты как в
  `benchlib.redact`. Длинные строки S3 (`stat`) склеены.
- `<ГГГГ-ММ-ДД>/events.jsonl` — индекс событий, по одному JSON в строке.
- `state.json` — замок (переживает перезапуск службы); `run-<порт>.json` — пока служба работает (по нему инструменты
  находят службу без сетевого запроса); `jobs/` — вывод заданий (прошивка, `call_check`).

## События

Из строк прошивки (`tools/bench/bench_events.py`, шаблоны — из `main.c`, `lyrat_ota.c`, `s3_ota.c`, `main.c` S3 ветки
`phone-bringup`):

| Тип | Когда |
|---|---|
| `boot` | новый boot id платы; причина из первой строки LyraT `BOOT reset_reason=X code=N` (`reason`, `code`), иначе `UNKNOWN` |
| `slc_up` / `slc_down` / `hfp_down` / `acl_down` | связь с телефоном: `SLC CONNECTED`, `SLC DOWN after N s, last_acl_reason=…`, `HFP conn state=0`, `ACL DOWN reason=…` |
| `sco_open` / `sco_close` | канал гарнитуры, `codec` (CVSD/mSBC); закрытие и при перезапуске LyraT |
| `ota_start` / `ota_done` / `ota_fail` / `ota_rollback` | обновления обеих плат (`receiving … into`, `new image in …`, `self-test passed/failed`, `lyrat rolled back`, …) |
| `panic` | Guru Meditation, abort, brownout reset, переполнение стека |
| `bod` | вырос счётчик `bod … trips=N` (просадки питания LyraT) |
| `net_down` / `net_up` | Wi-Fi S3 (`wifi lost`, `wifi off`, `wifi ip`) |
| `mic_mute` | микрофон LyraT выключен/включён (гоал 111): `state` on/off, `src` key (кнопка Rec) / cmd / boot, из строки `MIC MUTE on|off src=…` |

Свои события службы: `board_lost` / `board_back` (S3 не отвечает на `UQ` и молчит в логе; LyraT — нет кадров по UART
дольше `--lost-s`), `log_gap` (потери строк: на плате / в пути), `cmd` (команды через службу: кто, что, итог), `lock`
(взят / отдан / истёк / снят / действие поверх чужого замка), `job` (старт / итог задания), `benchd` (старт / стоп),
`s3_found` / `s3_search`.

## Страница владельца

`http://127.0.0.1:5080/` — одна страница без внешних файлов: состояние плат (адрес, boot, аптайм, rssi, версия, канал
гарнитуры) и телефона (если есть `adb` — только «подключён ли» и модель), замок и очередь, события за час, хвост лога с
фильтром по плате и регулярному выражению. Кнопки: перезапуск LyraT (`reboot 1`), перезапуск S3 (`UX`), режим BT (если
задан `--bt-mode-cmd`), прошить обе платы (`fw.py flash --board both`), `call_check --probe 1`, взять стенд себе на час /
отдать / снять чужой замок. Каждая опасная кнопка спрашивает подтверждение; если стенд держит гоал — второе
подтверждение, и действие пишется событием `lock overridden`.

С другого устройства в сети: `benchd.py --lan` — страница и чтение работают, кнопки отвечают отказом; управление из
сети — только с `--lan-control` **и токеном** (страница не с 127.0.0.1 показывает поле «токен управления», запоминает его
в браузере). Брандмауэр Windows спросит про python при первом `--lan`.

Страница **генерируется** (гоал 104): что на ней — панели, поля, кнопки, ленты — описано в
`lyrat_resend/tools/bench/bench_ui_spec.json`; из неё же собирается экран «Стенд» на телефоне. Руками
`benchd_admin.html` не правится (метка «generated, do not edit»), см. «Как добавить кнопку».

## Пульт на телефоне

Экран «Стенд» в нашем приложении `sco_probe` — те же панели и кнопки, что на странице, нативными виджетами. Телефон
ходит к benchd по домашней Wi-Fi (HTTP), управление — с токеном. **Адрес ПК вводить не нужно** (гоал 105): телефон
находит службу сам.

1. На ПК запустить службу с сетью и управлением:
   ```
   python lyrat_resend/tools/bench/benchd.py --lan --lan-control
   ```
   При первом запуске с `--lan-control` служба создаёт токен `bench_runs/benchd/lan_token.txt` (вне git).
   Брандмауэр Windows должен пускать python (TCP 5080, UDP 5082) в частной сети.
2. Телефон по USB (adb), приложение поставить/обновить и один раз передать токен:
   ```
   python lyrat_resend/tools/android/build_apk.py --install
   python lyrat_resend/tools/bench/bench.py phone-link
   ```
   `phone-link` кладёт `{token}` файлом в папку приложения (`Android/data/com.openvoicebridge.scoprobe/files/bench_link.json`)
   и открывает экран; приложение переносит токен в свои настройки и **удаляет файл**. Адрес не передаётся;
   `--host IP:PORT` — только подсказка (приложение её проверяет как любой адрес), `--forget` — забыть запомненный адрес.
   Токен не печатается (`bench.py lan-token` — показать). Без USB токен можно ввести на экране.
3. Открыть: кнопка «Стенд» на экране пробы, или `adb shell am start -n com.openvoicebridge.scoprobe/.MainActivity --es cmd bench`.

### Как телефон находит ПК

- **Когда ищет:** при открытии экрана и возврате к нему, после двух неудачных опросов службы подряд (≈4–6 с), при смене
  Wi-Fi (сеть или адрес телефона), по кнопке «Найти ПК». Не нашёл — повтор через 3, 6, 12, 24, 30… с, пока экран открыт.
- **Как:** сначала запомненный адрес (кэш) — запросом `GET /api/whoami?nonce=…`; не подтвердился — широковещание
  `BENCHD? 2 <nonce>` на UDP 5082 (три посылки на 255.255.255.255 и на широковещательный адрес подсети: в этой Wi-Fi
  одиночная посылка терялась примерно в одном случае из пяти). Multicast/mDNS (Android NSD) не используется: в этой Wi-Fi
  он от телефона до ПК не доходил вовсе (замер гоала 105).
- **Своя служба:** benchd отвечает своим id, именем ПК (`--name`, по умолчанию имя компьютера) и портом HTTP с подписью
  HMAC-SHA256 от токена. Телефон с токеном берёт только ответ с верной подписью на свой nonce; токен уходит только
  такой службе. Чужая служба (другой токен) и служба без подписи не берутся — экран пишет почему. Несколько служб:
  та, что была раньше (тот же id), иначе первая ответившая.
- **Адрес — только кэш:** запоминается после подтверждения, при каждом поиске проверяется заново. Адрес, введённый
  вручную, проверяется так же; не подтвердился — только просмотр без токена.
- Сокеты и HTTP идут через Wi-Fi, даже если Android считает основной мобильную сеть.

**Если не находит** (строка под заголовком говорит, что именно):
- «benchd запущен с --lan?» — служба без `--lan` не слушает сеть; новая служба нужна версии 105+ (подписанный ответ):
  «служба отвечает без подписи — старая версия» → перезапустить benchd;
- «подпись не сходится» — токен на телефоне от другого ПК или токен сменили → `bench.py phone-link`;
- брандмауэр Windows: python должен быть разрешён для UDP 5082 и TCP 5080 в профиле этой сети (у «Общедоступной» сети
  правила свои);
- изоляция клиентов в Wi-Fi (гостевая сеть, «AP isolation» роутера): устройства не видят друг друга — ни поиск, ни ввод
  вручную не помогут, нужна другая сеть;
- телефон не в той же Wi-Fi (или Wi-Fi выключен) — строка «нет Wi-Fi»;
- запасной путь — ввести `IP:5080` вручную и «Сохранить».

### Когда ПК выключен: напрямую с S3

Если **ни одна** служба benchd не ответила, а S3 ответила на `UQ`, экран переходит в режим «напрямую с S3»: шапка
«ПК не найден, замка нет — команды идут мимо службы». Работают: статус S3 и LyraT (по `UQ` и строкам `stat` лога), хвост
лога обеих плат на экране и **в файл приложения** (`files/direct_logs/<дата-время>.log`, MAC скрыты, до 20 МБ, старые
удаляются), «Перезапуск LyraT» (`UC … reboot 1`), «Перезапуск S3» (`UX <boot>`), «Команда консоли» (LyraT — любая
команда; S3 — только `query`, `restart`). Опасные — с подтверждением. Прошивка, замок, задания, события — только через
службу: кнопки видны, но отвечают «прошивка — только через службу на ПК: образы лежат на ПК». Что работает напрямую,
задаёт `via` в `bench_ui_spec.json` (`benchd` / `s3-direct`), `gen_bench_ui.py --check` это проверяет.

Забрать лог после включения ПК: `python lyrat_resend/tools/bench/bench.py phone-logs [--delete]` (adb, в
`bench_runs/phone_logs/<время>/`, вне git).

Без двойного управления: в прямом режиме телефон ищет benchd каждые 5 с и перед каждой командой; **любой** ответ
benchd (даже старой версии или чужой) — прямой режим выключается (`LOG0` S3), команда не посылается. Лог S3 отдаёт одному
слушателю: служба при старте забирает его как обычно, телефон отпускает его при следующем поиске (до 5 с; если лог
у телефона замолчал при живой S3 — ищет сразу). Экран свёрнут — прямой режим остановлен.

Известные ограничения: у реле S3 нет аутентификации (`S3_UART.md`) — любой в сети может слать те же команды, телефон
хуже не делает; если служба работает, но телефону недоступна (брандмауэр, другая сеть), телефон сочтёт ПК выключенным и
будет управлять напрямую мимо замка — об этом шапка и подтверждения. Подлинность ответа S3 не проверяется (секрета у неё
нет): это только чтение и команды, которые S3 и так принимает от любого.

На экране: строка ответа последнего действия сверху; режим (через службу / напрямую / ищу), строка поиска, строка S3
(«адрес совпадает со службой» / «расхождение — служба видит Y, телефон X» / «служба её не видит, телефон видит» /
«телефон её не видит»); «Найти ПК», «Обновить», ручной адрес и токен; панели «Платы», «Замок и задания», «Действия»,
ленты событий и лога. Опасные кнопки спрашивают подтверждение, при чужом замке — ещё раз. Замок у телефона и страницы
общий (`owner`), заметка замка — «владелец (телефон)».

Защита: без токена из сети — только чтение; `/shutdown` — только с ПК; токен сравнивается за постоянное время и на
телефоне уходит только подтвердившей службе. HTTP не шифруется: токен защищает от чужих устройств в сети, не от
прослушки Wi-Fi (тот, кто слушает Wi-Fi, может и переслать подписанный ответ со своего адреса). Сменить токен — удалить
`lan_token.txt`, перезапустить benchd, снова `phone-link`.

Проверки на телефоне без стенда (свои службы + эмулятор S3 на офсете 900; живая служба и настоящая S3 не затрагиваются):
`python lyrat_resend/tools/android/bench_screen_check.py` (пульт, гоал 104) и
`python lyrat_resend/tools/android/bench_find_check.py` (поиск, кэш, чужая/старая служба, прямой режим, возврат ПК).
На ПК: `run_tests.py --only bench_find` (Java телефона на JDK против benchd и эмулятора).

## Как добавить кнопку

1. Если нужного действия в службе нет — добавить его в `benchd.py`: строку в `ROUTES` (или имя в `ACTIONS` для
   `POST /action`) **и** обработчик (`make_handler` / `ACTION_RUN`; служба не стартует, если таблица и обработчики
   расходятся).
2. Описать кнопку в `bench_ui_spec.json` → `actions` (схема: `bench_ui_spec.md`): надпись, группа, маршрут, поля,
   `confirm` для опасного, `requires_lock`, `lan_control`.
3. Сгенерировать и проверить:
   ```
   python lyrat_resend/tools/bench/gen_bench_ui.py
   python lyrat_resend/tools/bench/gen_bench_ui.py --check --strict
   ```
   `--check` ничего не пишет и падает, если (a) сгенерированные файлы не совпадают со спецификацией, (b) кнопка ссылается
   на маршрут, метод, параметр или вариант, которого нет в benchd, (c) поле статуса нет в `/status` (служба + эмулятор),
   (d) у управляющего маршрута benchd нет кнопки (без `--strict` — предупреждение). Это же гоняет `run_tests.py`
   (`bench_ui_check`, `bench_ui`).
4. Пересобрать приложение (`build_apk.py --install`) — экран телефона берёт кнопку из сгенерированного `BenchSpec.java`.

## Для гоалов

### CLI `bench.py`

```
python lyrat_resend/tools/bench/bench.py status                       # платы, замок, задания, события за час
python lyrat_resend/tools/bench/bench.py logs --from -10m --board lyrat --grep "SLC|SCO"
python lyrat_resend/tools/bench/bench.py events --from 15:00 --to 15:10 --type boot,slc_down,board_lost
python lyrat_resend/tools/bench/bench.py tail --follow --board s3
python lyrat_resend/tools/bench/bench.py cmd "s"                      # консоль LyraT через S3, пишется событием
python lyrat_resend/tools/bench/bench.py cmd --s3 restart             # S3: query, restart, power [N], tx 0|1|A
python lyrat_resend/tools/bench/bench.py ota --board lyrat --wait     # fw.py flash заданием службы
python lyrat_resend/tools/bench/bench.py phone-link [--host IP:PORT] [--forget]   # токен на телефон (адрес он найдёт сам)
python lyrat_resend/tools/bench/bench.py phone-logs [--delete]       # логи прямого режима с телефона (ПК был выключен)
python lyrat_resend/tools/bench/s3_direct.py status                  # то, что телефон видит напрямую с S3 (не при живой службе)
python lyrat_resend/tools/bench/bench.py lock run --owner 104 --ttl 900 --wait 300 -- python lyrat_resend/tools/bench/round.py btloss ...
```

Время: ISO, `ЧЧ:ММ[:СС]` сегодня, или назад от сейчас: `-30s`, `-10m`, `-2h`, `-1d`. Коды выхода: 0 — сделано,
1 — отказ (при чужом замке печатается держатель), 2 — служба не запущена.

### Замок стенда

Перед окном измерения, прошивкой или перезапуском плат гоал берёт замок. Проще всего — обернуть команду:

```
bench.py lock run --owner 104 --ttl 900 --wait 300 -- <команда>
```

Это: взять замок (ждать в очереди до `--wait` с; иначе отказ с именем держателя), продлевать его каждые `ttl/3`, дать
команде `BENCH_LOCK_OWNER`/`BENCH_LOCK_TOKEN`, отдать замок в конце (и при ошибке команды). Если `bench.py` убит — замок
освобождается по смерти его pid; если гоал забыл продлить — по истечении `ttl` (не больше 4 ч). Очередь — по порядку
прихода, и держатель её не обходит (гоал 105): новый захват тем же владельцем, когда в очереди уже ждёт другой, встаёт за ним (без ожидания — отказ 409 с именем ожидающего); серия `lock run` одного гоала пропускает ждущих между командами. Продление `renew` с токеном и захват изнутри своей же команды (с её `BENCH_LOCK_TOKEN`) работают как раньше. Вручную: `bench.py lock acquire|renew|release --owner G`, `bench.py lock show`, `bench.py lock wait`.

`owner_common.bench_busy()` (шаги `owner_check`, `round.py`) при запущенной службе смотрит **на замок, а не на список
процессов**: замок у другого → «стенд занят: замок у «104» до 15:40»; свободен или наш (`BENCH_LOCK_OWNER`) → занятость
по процессам не проверяется, остальные проверки (LyraT по сети, порты потока) как раньше. Без службы — как до гоала 103.

Пока замок у одного гоала, `POST /cmd`, `/ota`, `/action` от другого получают 423 с именем держателя. Служба сама
спрашивает `bod` только при свободном замке, чтобы не вмешиваться в чужие окна.

### Инструменты работают и через службу, и без неё

Пока служба запущена (её находит `benchd_client.py` по файлу `run-5080.json`):

- `udplog.py`, `console.NetWatch` (значит `round.py`, `call_check.py`, `fw.py`, `s3.py`, …) берут лог у реле службы
  (127.0.0.1:5081, тот же протокол `LOG1/LOG0`, датаграммы `UL` как от S3, фильтр по уровням подписчика). Несколько
  инструментов и служба получают все строки одновременно, никто ни у кого не отбирает. В `summary.json` `udplog.py`
  поле `via`: `benchd` или `direct`. `udplog.py --direct` — спросить S3 напрямую (отберёт лог у службы на время работы).
- `s3_uart.Channel()` и `ota.find_host()` без адреса берут адрес S3 у службы — без широковещания.
- Команды на 5006 инструменты шлют сами, напрямую S3 (ответ приходит на порт отправителя, конфликтов нет). В индекс
  событий попадают только команды через `bench.py cmd` / `POST /cmd`.

Без службы всё работает как раньше. Отключить службу для процесса: `BENCH_NO_BENCHD=1`. Если `BENCH_S3_ADDR` указывает
не на ту S3, что у службы (например, тест на симуляторе 127.0.0.1), служба для лога и адреса не используется.

### API (HTTP/JSON, 127.0.0.1:5080)

| Запрос | Ответ |
|---|---|
| `GET /status` | `benchd` (pid, аптайм, файл, счётчики, диск), `s3` (addr, lost, boot, up_s, rssi, net, txp, ver, …), `lyrat` (lost, up_s, last_frame_ms, ver, sco_open, mic_muted — бит 2 флагов сердцебиения, null без него, гоал 111), `log_counts` (потери по платам), `phone`, `lock`, `jobs`, `events_last_hour`, `relay_port`, `subscribers` |
| `GET /logs?from=&to=&board=&grep=&limit=2000` | строки из файлов; при обрезке — последние `limit` и `truncated: true` |
| `GET /tail?after=ID&board=&grep=&limit=500` | новые строки из памяти (последние 5000) и `last_id` |
| `GET /events?from=&to=&type=a,b&limit=1000` | события |
| `GET /lock`, `GET /jobs`, `GET /jobs/<id>` | замок и очередь; задания; задание с хвостом вывода |
| `POST /lock {owner, ttl_s, wait_s, pid, note}` | 200 `{token}` или 409 `{holder, until, queue}` |
| `POST /lock/renew {owner, token, ttl_s}`, `POST /lock/release {owner, token}` | продлить / отдать |
| `POST /cmd {target: lyrat\|s3, cmd, owner, token}` | ответ консоли (`status`, `text`, `attempts`); 423 при чужом замке |
| `POST /ota {board: lyrat\|s3\|both, variant \| image, via}` | 202 и задание `fw.py flash` |
| `POST /action {name: reboot_lyrat\|restart_s3\|bt_mode\|flash_both\|call_probe}` | кнопки страницы |
| `POST /shutdown` | остановить службу (только с этого ПК) |
| `GET /api/routes` | таблица маршрутов `ROUTES` и действий `ACTIONS` (по ней проверяется пульт) |
| `GET /api/whoami?nonce=<16..64 hex>` | подписанный ответ обнаружения (id, имя, порт, `sig`), как на `BENCHD? 2 <nonce>` по UDP 5082 (гоал 105) |

Каждый POST требует заголовок `X-Bench: 1` (чужая веб-страница в браузере так послать не может); из сети ещё
`X-Bench-Token` (401 без него или с неверным). `"force": true` —
действие поверх чужого замка (пишется событием). Python: `benchd_client.call("GET", "/status")`,
`with benchd_client.Lock("104", ttl_s=900, wait_s=300): ...`.

## Порты, параллельные тесты

`BENCH_PORT_OFFSET=N` прибавляет N ко всем портам стенда в инструментах (5004–5010) и службы (5080/5081), а также к
портам по умолчанию симулятора `tests/s3_sim.py`. Прогоны тестов двух гоалов (worktree) на разных офсетах не мешают друг
другу: `python lyrat_resend/tools/run_tests.py --quick --port-offset 100`. Тесты службы сами берут офсет +600, чтобы не
встретить службу настоящего стенда. Прошивка порты не меняет: на стенде офсет всегда 0.

## Что не проверено без стенда

Всё выше проверено против симулятора S3 (`run_tests.py`, проверка `benchd`, `tests/test_benchd.py`). На железе не
запускалось (стенд обесточен на момент гоала 103): настоящий Wi-Fi и смена адреса по DHCP, поведение при часах работы
и сутках (ротация в полночь проверена на модельном времени), `adb` на странице, кнопки «прошить обе» и `call_check
--probe 1` (их пути — те же `fw.py` и `call_check.py`, задание службы проверено на `fw.py flash --image`).
